# 社外コラボレーターの招待

[README](../README.md) / [日本語 README](../README.ja.md) / [セットアップガイド](setup.md) / [Google OAuth セットアップ](google-oauth-setup.md)

組織ドメイン外の Google アカウント (他社の Workspace アカウントや個人の gmail.com) を、
プロジェクト単位で個別に招待して閲覧・コメントしてもらうための設定と運用手順。

## 何ができるか

- プロジェクトの visibility は **`domain` のまま変えずに**、メールアドレス単位で社外の人を追加できる
  (招待は visibility 設定に対する「追加の許可」として働く)
- 招待した相手は、そのプロジェクトの閲覧とコメントだけができる。プロジェクト作成・API キー発行・
  CLI 認証・デプロイはできない (`users.kind='guest'` として会員機能から隔離される)
- 招待と同時に、そのプロジェクトの Google Drive フォルダにも同じメールアドレスへ権限が付与される
  (権限は招待時に閲覧のみ / コメント可 / 編集可 から選択。通知メールは送られない)
- 招待を削除すると、publicar の閲覧も Drive の共有も同時に失効する

## 事前に必要な Google Cloud 側の設定

[Google OAuth セットアップガイド](google-oauth-setup.md) の手順どおりに
「外部 / 本番環境」で構築していれば、追加の設定は不要。

既に「内部」で運用している環境を社外共有に対応させる場合は、以下の変更が必要になる。
**この設定をしないと、社外アカウントはログイン画面にすら到達できず
`403: org_internal` (「アクセスをブロック: 組織内でのみ利用可能です」) で拒否される。**

### OAuth の対象を「外部」にする

1. [Google Cloud Console](https://console.cloud.google.com/auth/audience) の
   「Google 認証プラットフォーム」→「対象」(旧「OAuth 同意画面」) を開く
   - OAuth クライアント ID の先頭の数字がプロジェクト番号なので、それで対象プロジェクトを選ぶ
2. 「ユーザーの種類」が **内部** になっている場合、「外部に公開」を押す
3. 公開ステータスを聞かれたら **「本番環境」** を選んで確認する

既存プロジェクトのまま内部から外部へ変更でき、OAuth クライアント ID / シークレットの
作り直しは不要 (2026-07 時点の Google Cloud Console で確認)。

### 「テスト中」ではなく「本番環境」を選ぶ理由

| | テスト中 | 本番環境 |
|---|---|---|
| ログインできる人 | 手動で追加したテストユーザー 100 人まで | 誰でも (publicar 側で判定する) |
| Google の審査 | 不要 | **不要** (下記参照) |
| リフレッシュトークン | **7 日で失効** | 通常どおり |

publicar が要求するスコープは `openid` / `email` / `profile` /
[`drive.file`](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) の 4 つで、
いずれも Google の分類上 **非機密 (non-sensitive)**。
[アプリの確認が必要になるのは機密 (sensitive) 以上のスコープを使う場合](https://support.google.com/cloud/answer/13463073)
なので、publicar は審査なしで本番公開でき、同意画面に「確認されていないアプリ」の警告も出ない。

一方、[テストモードの外部アプリはリフレッシュトークンが 7 日で失効する](https://developers.google.com/identity/protocols/oauth2)
(名前・メール・プロフィールだけを要求する場合を除く)。publicar は `drive.file` も要求するため
この除外に当たらず、テストモードのままでは 7 日ごとに全ユーザーの再ログインが必要になる。

なお「対象」画面に表示される **「OAuth ユーザー数の上限 100」は、未承認の機密スコープを
要求する場合の制限**であり、非機密スコープのみを使う publicar には適用されない。

### 「外部」にしてもアクセス制御は緩まない

Google 側の入口が開くだけで、誰が使えるかは publicar が判定する。
`ALLOWED_SIGNUP_DOMAINS` に一致するドメインのアカウントか、いずれかのプロジェクトに
招待済みのメールアドレスでなければ、ログイン処理は 403 で拒否され、ユーザーもセッションも作られない。

## 招待の手順

1. owner としてログインし、プロジェクト詳細 →「メンバー」タブ →「外部コラボレーター招待」を開く
2. 相手のメールアドレスを入力し、**Drive 権限**を選ぶ
   - 閲覧のみ (reader) — 既定。Drive でファイルを見るだけ
   - コメント可 (commenter)
   - 編集可 (writer) — Drive 上でファイルを変更できる
3. 「招待を追加」を押す
4. 一覧の **Drive 列**を確認する
   - 権限名が表示されていれば Drive への反映も成功
   - 赤いエラーが表示された場合、publicar 上の招待は有効だが Drive 共有は未反映 (下記トラブルシューティング)
5. プロジェクトの URL (`https://<your-domain>/<alias>/`) を相手に伝える
   - 招待メールは publicar からも Drive からも送られないので、URL は自分で共有する
   - 相手が初回アクセスすると Google ログイン → 同意画面 (Drive の許可が表示される) → 閲覧できる

### 招待を取り消す

一覧の「削除」を押すと、publicar の閲覧権限と Drive の共有が同時に取り消される。

- publicar 経由で付与した権限だけが対象で、**Drive 側で手動追加した共有には触れない**
- Drive の取り消しに失敗した場合、招待は削除されずエラーが表示される。原因を解消してから
  もう一度削除すれば再試行できる (publicar では消えたのに Drive では見える、という食い違いを防ぐため)

## 招待した相手にできること・できないこと

| | 可否 |
|---|---|
| 招待されたプロジェクトの閲覧 | できる |
| コメントの投稿・自分のコメントの編集と削除 | できる |
| 他人のコメントの編集・削除 | できない |
| 招待されていないプロジェクトの閲覧 | できない |
| プロジェクトの作成 | できない |
| API キーの発行 / CLI 認証 | できない |
| デプロイ | できない |
| Drive 上のファイル操作 | 招待時に選んだ権限の範囲 |

## トラブルシューティング

### `403: org_internal` / 「組織内でのみ利用可能です」

OAuth の「ユーザーの種類」が内部のまま。上記「事前に必要な Google Cloud 側の設定」を実施する。

### ログインが 403 になる (同意画面までは出る)

招待されていないアカウント。`ALLOWED_SIGNUP_DOMAINS` 外かつ、どのプロジェクトにも
招待が無い場合は仕様どおり拒否される。招待を追加してから再度ログインしてもらう。

### 招待一覧の Drive 列にエラーが出る

publicar 上の閲覧・コメントは使えるが、Drive の共有だけが未反映の状態。表示される理由ごとの原因:

| 表示 | 原因と対処 |
|---|---|
| `domainPolicy` を含む | Google Workspace 管理設定で外部共有が禁止されている。管理コンソールの共有ドライブ設定を確認する |
| `sharingRateLimitExceeded` を含む | Drive の共有レート制限。時間を置いて再度招待する |
| `Drive フォルダ未作成のため未反映` | そのプロジェクトにまだ 1 度もデプロイしていない。デプロイして Drive フォルダを作ってから再度招待する |

同じメールアドレスをもう一度招待すると再試行になる (既に権限がある場合は権限の変更として扱われ、
Drive 側に重複した共有は作られない)。
